# مستند هندآف (Hand-off) پروژه BaziGB

تاریخ: ۱۸ مرداد ۱۴۰۵
وضعیت پروژه: بچ ۱۰ تکمیل شد - قوانین کامل کارت‌های پول وگاس (۵۴ کارت، ۵ راند) پیاده‌سازی شد

## وضعیت فعلی
پلتفرم BaziGB اکنون دارای ۴ بازی فعال است. زیرساخت موتور بازی (Engine) برای پشتیبانی از نوبت‌های چند مرحله‌ای ارتقا یافته است.
- **Engine Core:** پشتیبانی از سیستم `applyAction` برای حرکت‌های متوالی در یک نوبت (بدون تغییر اجباری نوبت).
- **Vegas Plugin:** پیاده‌سازی کامل بازی استراتژیک وگاس با سیستم تاس‌ریزی دستی، قوانین کامل کارت‌های پول (بر اساس بازی رسمی Vegas + قوانین خانگی پروژه).
- **Server Gateway:** اضافه شدن هندلر `gameAction` + هندلر `nextRound` برای راندهای وگاس.

- [x] بهبود سیستم تعاملات تخته‌نرد با استفاده از اکشن‌های جدید.
- [x] **بازنویسی منطق کارت‌های پول وگاس** (بچ ۱۰): ۵۴ کارت (۶ تا از هر ارزش ۱۰هزار تا ۹۰هزار)، هر راند شافل و توزیع رندوم در ۶ استک دوتایی؛ استک‌ها بر اساس مجموع ارزش چیده می‌شوند (گران‌ترین روی خونه ۶).
- [x] **قوانین تسویه هر خونه:** نفر اولِ بی‌رقیب کارت بالاتر را می‌برد و نفر دومِ بی‌رقیب کارت پایین‌تر؛ تساوی در هر رتبه = کارت سوخته (از بازی خارج می‌شود).

- [x] **نمایش تفکیکی تاس هر بازیکن** روی هر خونه (رنگ + تعداد + برچسب P1/P2) — رفع ناسازگاری کلیدهای ایندکس/سوکت‌آیدی.

- [x] **رفع بلوک سفید موبایل هنگام زوم‌اوت:** برچسب‌های Nav در موبایل مخفی شدند + `overflow-x: clip` در globals.css.

### قوانین نهایی بازی وگاس (بچ ۱۰)
- **کارت‌های پول:** ۵۴ کارت، ۶ نسخه از هر ارزش ۱۰٬۰۰۰ تا ۹۰٬۰۰۰ دلار. هر راند کل دسته شافل می‌شود و ۶ استک دوتایی (۱۲ کارت) به صورت رندوم بسته می‌شود.
- **چیدمان استک‌ها:** استک‌ها بر اساس مجموع ارزش مرتب می‌شوند — گران‌ترین روی خونه ۶، بعدی روی خونه ۵، … کم‌ارزش‌ترین روی خونه ۱. (مجموع مساوی: کارت بالاتر بالاتر می‌نشیند.)
- **تعداد راندها:** دقیقاً ۴ راند (هر راند ۱۲ کارت = ۴۸ کارت از ۵۴ کارت؛ ۶ کارت آخر بدون استفاده می‌مانند). بعد از راند ۴ برنده مشخص می‌شود و راند ۵ وجود ندارد.
- **جریان بازی:** هر بازیکن در نوبتش تاس‌های باقیمانده‌اش را می‌ریزد، یک عدد را انتخاب و همه تاس‌های همان عدد را روی خونه‌ی همان عدد می‌گذارد؛ بقیه تاس‌ها برای نوبت‌های بعدی می‌مانند. وقتی تاس همه تمام شد راند تسویه می‌شود.
- **تسویه:** برنده بی‌رقیب هر خونه کارت بالاتر، نفر دوم بی‌رقیب کارت پایین‌تر. تساوی در صدر = کل استک می‌سوزد؛ تساوی در رتبه دوم = کارت پایینی می‌سوزد؛ خونه بدون تاس = کل استک می‌سوزد.
- **قانون خانگی ۸ تاس:** ۸ تاس روی یک خونه = Sweep (هر دو کارت + انکار نفر دوم). تساوی دو نفره در ۸ = سوخته.
- **پایان بازی:** بعد از راند ۴ برنده = بیشترین پول؛ تساوی = تعداد کارت‌ها؛ باز هم تساوی = مساوی (draw).
- **سوختن کارت‌ها:** کارت‌های سوخته از جریان بازی خارج می‌شوند (در همان راند حذف می‌شوند و برای راند بعد استفاده نمی‌شوند).

## گام‌های بعدی پیشنهادی
۱. **پنل مدیریتی (Admin Panel):** تعریف نقش ادمین (فیلد role + ادعای JWT + گارد) و ساخت Admin API + صفحه `/admin` — تسک‌ها در سیستم تسک تعریف شده‌اند.
۲. **سیستم Undo/Redo:** اضافه کردن قابلیت بازگشت به عقب در بازی‌های استراتژیک.
۳. **تکمیل تعاملات تخته‌نرد:** نهایی کردن سیستم Drag & Drop و قوانین پیشرفته حرکت.
۴. **نوتفیکیشن‌های پوش:** اطلاع‌رسانی نوبت بازی به کاربران.
۵. **بهبود انیمیشن‌ها:** استفاده از فیزیک برای حرکت طبیعی‌تر تاس‌ها.

## تصمیمات باز (Open Decisions) — فعلاً فقط ثبت شده، نیاز به تصمیم‌گیری بعدی
- **الگوریتم حذف/بستن بردها و رکوردها:** اینکه بردها و رکوردهای بازی چگونه از لیدربورد و تاریخچه حذف شوند (حذف نرم + ممیزی + بازگردانی آمار + پاکسازی دورهای با کران) هنوز تصمیم‌گیری نشده است. **این موضوع فقط در اینجا ثبت شده و تا تصمیم بعدی در مورد راهکار و نحوه اجرا، هیچ‌کاری انجام نمی‌شود.**

## پروتکل عملیاتی BaziGB (مهم برای هوش مصنوعی)

برای حفظ نظم و جلوگیری از شلوغی Context، تمام تسک‌ها باید طبق این پروتکل انجام شوند:

۱. **دسته بندی (Batching):** تسک‌ها بر اساس نقشه راه (Roadmap) به گروه‌های حداکثر ۵تایی تقسیم می‌شوند.
۲. **برون‌سپاری (Delegation):** انجام تسک‌ها به ساب‌ایجنت‌ها (`sessions_spawn`) سپرده می‌شود. هر ساب‌ایجنت مسئول یک خروجی مشخص و مستقل است.
۳. **تأیید و ادغام (Verify & Merge):** پس از اتمام کار ساب‌ایجنت‌ها، ایجنت اصلی نتایج را وریفای کرده و با کد اصلی مرج می‌کند.
۴. **بروزرسانی مستندات:** پس از هر بچ، تمام مستندات فنی و فایل `HANDOFF.md` بر اساس تغییرات جدید آپدیت می‌شوند.
۵. **ثبت نهایی (Push):** پس از تأیید نهایی هر بچ ۵تایی، کدها به مخزن GitHub پوش می‌شوند.
